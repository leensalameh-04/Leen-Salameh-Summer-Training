🎯 Project Description

Build a Task Management REST API using Spring Boot. System allows users to create projects, add/manage tasks, assign priorities and due dates, update task status, filter results, validate requests, store data in relational DB, handle errors, and test main components.

🏁 Final Delivery Outcome

  • Structured REST API with controller, service, repository, model, DTO, mapper, and exception layers.
  • Persistent Project & Task entities with `@OneToMany` / `@ManyToOne` relationship.
  • Unit, MockMvc controller, and repository tests.
  • Profiles (`dev` H2 vs `prod` PostgreSQL), Actuator, and Executable JAR.

Defense Prep

Project Defense Q&A Guide

Click any question to reveal the recommended answer for your presentation defense:

❓ Why did you use DTOs instead of returning @Entity classes directly? ▼
💡 "Returning entities directly causes infinite circular JSON recursion due to bidirectional relationships like Task-Project. DTOs decouple our API contract from the database schema, enable declarative input validation (@Valid), and prevent security vulnerabilities like over-posting."
❓ What is the benefit of using @RestControllerAdvice for exception handling? ▼
💡 "It provides centralized exception interception across the entire application. Unhandled exceptions are caught centrally by GlobalExceptionHandler and converted into uniform ErrorResponse JSON bodies with proper HTTP status codes (404 Not Found, 400 Bad Request, 409 Conflict)."
❓ How does dynamic query filtering work in TaskServiceImpl? ▼
💡 "We implemented Spring Data JPA Specification, which uses the JPA Criteria API to dynamically construct SQL WHERE clauses based on whichever query parameters (status, priority, projectId, overdue) are provided in the HTTP request, combined with Pageable pagination and sorting."
❓ How do environment profiles work in application.properties? ▼
💡 "Spring profiles isolate environment configuration. In the 'dev' profile, the app uses an in-memory H2 database. In the 'prod' profile, Spring dynamically reads environment variables (DB_URL, DB_USERNAME, DB_PASSWORD) to connect to PostgreSQL without code modification."
